# 배포 전 점검: 운영·프론트엔드 연동 리스크

작성일 2026-11-12. PR #7(컨테이너·prod 보안)과 PR #8(ECR·OIDC·SSM 배포)이 설명대로 병합·동작한다고
가정하고, 그 상태로 서비스에 올라갔을 때와 프론트엔드가 붙을 때 생길 문제를 정리했다.
두 PR의 diff와 develop의 애플리케이션·Terraform 코드를 읽어서 확인한 내용이며, 실제 서버에
배포해서 재현한 것은 아니다.

분석하는 동안 PR #7이 후속 커밋과 함께 병합됐고 PR #8 브랜치에도 수정이 추가됐다. 그 수정으로
이미 해결된 항목은 "해결됨"으로 표시했다. 기준 시점은 develop `85d4133`, PR #8 브랜치 `38c53d0`이다.

## 요약

배포 파이프라인 자체는 동작하겠지만, 지금 상태로 올리면 프론트엔드는 **기능 API를 하나도 쓸 수 없다.**
막는 요인은 세 가지다. 인증 발급처가 정해지지 않아 모든 API가 401이고, 주차장 데이터를 넣을 경로가
없어 조회가 비어 있으며, HTTP 평문이라 모바일 앱과 HTTPS 웹에서 호출 자체가 차단된다.
이 세 가지는 코드만으로 해결되지 않고 결정이 필요하다(아래 "결정이 필요한 항목").

코드로 바로 고칠 수 있는 것 중 아직 남아 있던 항목은 두 PR로 올렸다.

| PR | 내용 | 해결하는 항목 |
|---|---|---|
| #13 (base: develop) | prod CORS 설정과 테스트 | F3 |
| #14 (base: PR #8 브랜치) | 컨테이너 로그 용량 제한, 앱 종료 유예 시간 | O5 일부, O6 일부 |

PR #7·#8의 후속 커밋으로 이미 해결된 항목: F2(인증 실패 응답 포맷), F4(Swagger 인증),
O1(배포 전 테스트).

## 프론트엔드 연동

### F1. issuer가 없으면 모든 기능 API가 401 (높음)

`ProdSecurityConfig`는 issuer가 비어 있으면 리소스 서버를 켜지 않는다. 안전한 기본값이지만
Terraform 부트스트랩이 만드는 `/opt/hmc/.env`의 `OAUTH2_ISSUER_URI`가 빈 값이라, 배포 직후
프론트엔드가 호출할 수 있는 것은 Swagger 화면과 `/actuator/health`뿐이다.
`CurrentUserIdArgumentResolver`도 `JwtAuthenticationToken`만 받으므로 우회 경로는 없다.

개선: 발급처를 정하고 `.env`에 넣는다. 그 전에 프론트엔드가 개발을 시작해야 하면 `local`
프로필로 띄운 서버나 응답 예시(Mock)를 따로 제공한다. prod에 인증 우회를 넣는 것은 권하지 않는다.

### F2. 401·403 응답 본문이 비어 있다 (해결됨)

처음 PR #7은 `HttpStatusEntryPoint`로 상태 코드만 보냈다. 병합된 버전은 필터 단계의 401·403을
`ApiResponse.fail(...)`(`COMMON4011`, `COMMON4031`)로 쓰고, 리소스 서버 필터에도 같은 핸들러를
적용한다. 프론트엔드는 모든 실패에서 `error.code`를 읽을 수 있다.

### F3. CORS 설정이 없다 (웹 프론트엔드라면 높음, #13에서 수정)

브라우저는 `Authorization` 헤더가 붙은 요청 전에 `OPTIONS` preflight를 보낸다. 지금은 preflight가
인증 대상이라 401이 나고, 실제 요청은 나가지도 않는다. 네이티브 앱만 쓴다면 영향이 없다.
#13은 `CORS_ALLOWED_ORIGINS`에 등록한 출처만 허용한다.

### F4. Swagger UI에서 토큰을 넣을 수 없다 (해결됨)

병합된 PR #7에 bearer JWT 보안 스킴(`OpenApiConfig`)이 들어가 Authorize 버튼으로 토큰을 넣을 수 있다.

### F5. 주차장·예측 데이터를 넣을 방법이 없다 (높음)

`ParkingLotWriteService.register`는 있지만 호출하는 컨트롤러가 없고, 만차율 예측을 쓰는 코드도
없으며, 마이그레이션에 시드 데이터도 없다. 운영 DB는 빈 상태로 시작한다. 그 결과:

- `GET /api/v1/parking-lots/nearby`는 항상 빈 배열
- 도착 outlook의 `destinationParkingLot`은 null, `destinationForecasts`는 빈 배열
- 브리핑의 `recommended`는 null, `alternatives`는 빈 배열
- `parkingLotId`를 보내는 요청은 전부 주차장 없음 오류

프론트엔드는 화면을 채울 데이터가 없어 핵심 흐름(①대기 화면, ②브리핑)을 검증할 수 없다.

### F6. HTTP 평문, IP와 8080 포트 (높음)

배포 문서도 "현재 HTTP 구성은 Swagger 확인용"이라고 적고 있다. 구성 자체는 아직 없다.

- iOS는 ATS로, Android는 9 이상에서 기본값으로 평문 HTTP를 차단한다. 앱에 예외 설정을 넣어야만 호출된다.
- HTTPS로 서비스되는 웹 페이지에서는 혼합 콘텐츠로 차단된다.
- JWT가 평문으로 오간다.
- `create_elastic_ip=false`면 인스턴스를 재시작할 때 주소가 바뀐다.

### F7. 시각은 모두 UTC, ISO-8601 (중간)

요청의 `at`, `from`, `to`, `expectedArrivalAt`은 `Instant`라서 `2026-11-12T09:00:00Z`처럼 오프셋이
붙은 형식만 받는다. `2026-11-12T18:00:00`(오프셋 없음)은 400이다. `nearby`의 `at`은 필수다.
응답도 UTC(`Z`)로 나가므로 화면에는 프론트엔드가 KST로 바꿔 보여야 한다. 만차율 예측은 30분
슬롯 단위다. Swagger 설명에 형식 예시를 넣어 두는 편이 좋다.

### F8. "없음"이 404로 온다 (중간)

진행 중인 도착 세션이나 주차 기록이 없으면 `GET .../active`가 404와 도메인 에러 코드를 준다.
앱을 켤 때마다 호출하는 API라서 정상 상황인데도 에러 로그와 에러 처리 분기가 생긴다.
프론트엔드와 합의해 404를 유지할지, `200`에 `data: null`로 바꿀지 정해야 한다.

### F9. 그 밖의 계약 관련 사항 (낮음)

- `congestionLevel`은 문자열, `status`는 enum이라 Swagger에 허용 값이 한쪽만 노출된다.
- `nearby`는 최대 10개 고정이고 페이지 개념이 없다. 저장 장소 목록도 전체 반환이다.
- 검증 실패(`COMMON4001`)는 메시지 문자열 하나라 어느 필드가 틀렸는지 구조적으로 알 수 없다.
- 사용자는 JWT `sub`만으로 식별한다. 발급처를 바꾸거나 둘 이상 쓰면 다른 사람이 같은 계정에 묶일 수 있다.

## 운영

### O1. 테스트 없이 운영에 배포된다 (해결됨, PR #8 후속 커밋)

처음 PR #8은 테스트 없이 빌드·배포했다. 지금 브랜치는 PR과 develop push에서 `./gradlew check`를
먼저 돌리고 통과해야 배포하며, `DEPLOY_ENABLED=true`를 설정하기 전에는 배포 job을 건너뛴다.
문서만 바꾼 변경은 워크플로가 실행되지 않으므로, 브랜치 보호에서 이 검사를 필수로 지정하면
문서 전용 PR이 병합 대기 상태로 남는다는 점만 주의한다.

### O2. develop push가 곧 운영 배포, 마이그레이션은 되돌릴 수 없다 (높음)

`DEPLOY_ENABLED=true`를 설정한 뒤의 이야기다. 그 전에는 배포 job이 실행되지 않는다.

스테이징이 없고 Flyway는 앱 기동 때 자동 적용된다. 배포 문서도 "DB 마이그레이션은 자동으로
되돌리지 않는다"고 적고 있다. 컬럼 삭제 같은 변경이 병합되면 이전 이미지로 되돌려도 스키마가
맞지 않아 기동에 실패한다(`ddl-auto: validate`). SSM 권한은 인스턴스에서 root로 임의 명령을
실행할 수 있으므로, develop에 push할 수 있는 사람은 사실상 서버 관리자다.

개선: develop 브랜치 보호(필수 리뷰, 필수 상태 검사), 운영 배포 트리거 분리, 마이그레이션은
추가 → 코드 전환 → 삭제 순서로 나눠 배포.

### O3. DB 백업이 없다 (높음)

배포 문서에 "운영 데이터 저장 전 준비"로 적혀 있지만 절차와 스크립트는 아직 없다.

PostgreSQL 데이터는 EC2 한 대의 EBS 볼륨에 있고 스냅샷이나 덤프가 없다. 인스턴스 교체, 볼륨
손상, 잘못된 마이그레이션 중 하나만 일어나도 복구할 수 없다.

개선: `pg_dump`를 하루 한 번 이미 있는 S3 버킷으로 올리는 cron(또는 EBS 스냅샷 수명 주기 정책).
배포 스크립트에서 마이그레이션 전에 덤프를 한 번 뜨는 것도 방법이다.

### O4. 메모리 여유가 적다 (중간, 일부 완화됨)

t3.micro(1GB)에 앱(512MB), PostgreSQL(256MB), Redis(64MB)가 함께 돈다. PR #8 후속 커밋이 컨테이너별
제한을 넣고 힙 비율을 50%(약 256MB)로 낮췄지만, PR #7의 측정으로 앱은 유휴 상태에서 이미 381MB였다.
부하가 걸리면 앱 컨테이너가 OOM으로 죽고 재시작하는 동안 요청이 실패한다. Redis는 32MB에서
`noeviction`이라 가득 차면 쓰기가 실패한다(현재 Redis를 쓰는 코드는 없다).

개선: 간단한 부하 테스트로 실제 사용량을 확인하고, 부족하면 t3.small로 올린다.

### O5. 배포할 때마다 서비스가 끊긴다 (중간, 일부 #14)

인스턴스가 하나이고 compose가 앱 컨테이너를 교체하므로 JVM이 뜨는 수십 초 동안 요청이 실패한다.
Docker 기본 종료 유예는 10초라 처리 중이던 요청도 끊긴다. #14에서 유예 시간을 늘리고 문서에
명시했다. 무중단이 필요해지면 프록시 뒤에서 새 컨테이너를 먼저 띄우는 방식으로 바꿔야 한다.

### O6. 로그와 모니터링 (중간, 일부 #14)

- 컨테이너 로그에 용량 제한이 없어 DB와 같은 디스크를 채운다. #14에서 제한을 넣었다.
- Loki appender 의존성은 있지만 logback 설정이 없어 로그는 서버 안에만 남는다. 장애 때 SSM으로 접속해야 본다.
- `/actuator/prometheus`는 노출 설정만 있고 prod에서는 인증 대상이라 수집할 수 없다. 알림도 없다.
  서버가 죽어도 누군가 호출해 보기 전에는 알 수 없다.

개선: 최소한 외부 가동 확인(UptimeRobot 등으로 `/actuator/health`)을 하나 건다.

### O7. Swagger와 API가 전 세계에 열려 있다 (중간)

`app_allowed_cidrs` 기본값이 `0.0.0.0/0`이고 Swagger는 인증 없이 열린다. API 구조가 공개되고,
요청 수 제한이 없어 스캐너 트래픽을 그대로 받는다. 심사·데모 기간에는 CIDR을 좁히거나, Swagger를
환경변수로 끌 수 있게 한다.

### O8. 서버의 `.env`는 처음 한 번만 만들어진다 (낮음)

`user_data`는 첫 부팅에만 실행되고 Terraform이 변경을 무시한다. 새 환경변수(`CORS_ALLOWED_ORIGINS`,
issuer 등)는 서버에 직접 추가해야 하며, 빠뜨려도 앱은 기본값으로 뜨기 때문에 알아채기 어렵다.
배포 문서에 필수 변수 목록을 두고, 배포 스크립트가 필수 키를 검사하게 하면 좋다.

### O9. 빌드 디렉터리를 바꾸면 ArchitectureTest가 실패한다 (낮음)

`ArchitectureTest`는 `DO_NOT_INCLUDE_TESTS`로 테스트 클래스를 제외하는데, 이 옵션은 경로에
`/build/classes/`가 있는지로 판단한다. `-PhmcBuildDir`로 경로 끝이 `build`가 아닌 곳을 지정하면
테스트 클래스가 검사 대상에 들어가 도메인 의존 규칙 위반으로 실패한다. 이번 작업 중 실제로 겪었다.
`hmcBuildDir`은 `.../build`로 끝나는 경로를 쓰도록 문서에 적거나, 패키지 기준 제외로 바꾼다.
