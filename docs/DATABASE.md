# 데이터베이스 구조

- 기준: `src/main/resources/db/migration/V1__init.sql` (PostgreSQL 16 + PostGIS 3.4)
- 도메인 경계 근거: `docs/overnight/DECISIONS.md` D4~D6, 화면 근거: `docs/overnight/figma-spec.md`
- ERD 작도용 DDL: [`docs/erd/hmc-erd.sql`](erd/hmc-erd.sql)
- 스키마를 바꾸면(새 `V{n}__*.sql`) 이 문서와 `docs/erd/hmc-erd.sql`을 함께 갱신한다.

## 1. 설계 원칙

- 도메인 사이 참조는 FK 없이 `BIGINT` ID와 인덱스로만 한다. FK는 같은 도메인 안에서만 둔다(현재 `parking_lot_occupancy_forecasts` → `parking_lots` 하나).
- 위치는 `geometry(Point, 4326)`(WGS84 경도/위도)이다.
- 모든 테이블에 `created_at`, `updated_at`(`TIMESTAMPTZ`, NOT NULL)이 있다. 아래 표에서는 생략한다.
- PK는 `BIGINT GENERATED BY DEFAULT AS IDENTITY`이다.
- 인증은 외부 Issuer가 담당하므로 `users`는 최초 요청 시 JWT `sub`로 생성하는 최소 테이블이다.

## 2. 관계도

```
users (user)
 ├─< saved_places       (place)     user_id
 ├─< arrival_sessions   (arrival)   user_id
 └─< parking_records    (parking)   user_id

parking_lots (parkinglot)
 ├─< parking_lot_occupancy_forecasts   parking_lot_id   [실제 FK]
 ├─< arrival_sessions   destination_parking_lot_id, waypoint_parking_lot_id
 └─< parking_records    parking_lot_id (nullable)
```

`[실제 FK]` 외의 선은 ID 참조만 있고 DB 제약은 없다.

## 3. 테이블

### 3.1 user

**users**

| 컬럼 | 타입 | 제약 | 설명 |
|---|---|---|---|
| id | BIGINT | PK | |
| auth_subject | VARCHAR(255) | NOT NULL, UNIQUE | 외부 Issuer JWT의 `sub` |

### 3.2 place

**saved_places** — 사용자 저장 장소

| 컬럼 | 타입 | 제약 | 설명 |
|---|---|---|---|
| id | BIGINT | PK | |
| user_id | BIGINT | NOT NULL | → users.id (논리) |
| name | VARCHAR(50) | NOT NULL | |
| location | geometry(Point,4326) | NOT NULL | |

- UNIQUE `(user_id, name)`: 사용자별 장소 이름 중복 불가

### 3.3 parkinglot

**parking_lots** — 주차장

| 컬럼 | 타입 | 제약 | 설명 |
|---|---|---|---|
| id | BIGINT | PK | |
| name | VARCHAR(100) | NOT NULL | |
| location | geometry(Point,4326) | NOT NULL | GIST 인덱스 |
| indoor | BOOLEAN | NOT NULL | 실내 여부 |
| entrance_guide | VARCHAR(255) | | 입구 안내 |
| free_minutes | INTEGER | NOT NULL, DEFAULT 0 | 무료 시간(분), `>= 0` |
| fee_unit_minutes | INTEGER | | 요금 단위(분) |
| fee_unit_price | INTEGER | | 단위당 요금 |
| total_spaces | INTEGER | | 총 면수, NULL 또는 `> 0` |

- CHECK `ck_parking_lots_fee`: `fee_unit_minutes`/`fee_unit_price`는 둘 다 NULL이거나(`fee_unit_minutes > 0` 이고 `fee_unit_price >= 0`)

**parking_lot_occupancy_forecasts** — 시간대별 혼잡도 예측

| 컬럼 | 타입 | 제약 | 설명 |
|---|---|---|---|
| id | BIGINT | PK | |
| parking_lot_id | BIGINT | NOT NULL, **FK** → parking_lots.id | |
| target_at | TIMESTAMPTZ | NOT NULL | 예측 대상 시각 |
| occupancy_rate | SMALLINT | NOT NULL | 0~100 |

- UNIQUE `(parking_lot_id, target_at)`

### 3.4 arrival

**arrival_sessions** — 도착 모드(안내) 세션

| 컬럼 | 타입 | 제약 | 설명 |
|---|---|---|---|
| id | BIGINT | PK | |
| user_id | BIGINT | NOT NULL | → users.id (논리) |
| destination_name | VARCHAR(100) | NOT NULL | |
| destination_location | geometry(Point,4326) | NOT NULL | |
| destination_parking_lot_id | BIGINT | | → parking_lots.id (논리) |
| waypoint_parking_lot_id | BIGINT | | → parking_lots.id (논리), 경유 주차장 |
| expected_arrival_at | TIMESTAMPTZ | NOT NULL | |
| status | VARCHAR(20) | NOT NULL | `ACTIVE` / `COMPLETED` / `CANCELLED` |
| ended_at | TIMESTAMPTZ | | 종료 시각 |

- CHECK: `(status = 'ACTIVE') = (ended_at IS NULL)`
- 부분 UNIQUE `(user_id) WHERE status = 'ACTIVE'`: 사용자당 진행 중 세션 1개
- 인덱스: `user_id`, `destination_parking_lot_id`, `waypoint_parking_lot_id`

### 3.5 parking

**parking_records** — 주차 기록

| 컬럼 | 타입 | 제약 | 설명 |
|---|---|---|---|
| id | BIGINT | PK | |
| user_id | BIGINT | NOT NULL | → users.id (논리) |
| parking_lot_id | BIGINT | | → parking_lots.id (논리), 주차장 밖이면 NULL |
| location | geometry(Point,4326) | NOT NULL | 주차 위치 |
| parked_at | TIMESTAMPTZ | NOT NULL | |
| spot_memo | VARCHAR(100) | | 주차 구역 메모 |
| sent_to_phone_at | TIMESTAMPTZ | | 폰 전송 시각 |
| exited_at | TIMESTAMPTZ | | 출차 시각 |

- CHECK: `exited_at IS NULL OR exited_at >= parked_at`
- 부분 UNIQUE `(user_id) WHERE exited_at IS NULL`: 사용자당 미출차 기록 1개
- 인덱스: `(user_id, parked_at DESC)`, `parking_lot_id`

| 인덱스 | 테이블 | 종류 |

| idx_parking_lots_location | parking_lots | GIST (location) |

## 5. ERD 그릴 때 참고

- `docs/erd/hmc-erd.sql`은 V1과 같은 테이블에 도메인 간 ID 참조를 `lfk_*` 논리 FK로 추가한 파일이다. 도구에서 관계선이 자동으로 그려진다. 실제 DB에는 이 FK가 없다.
- `geometry(Point, 4326)`을 인식하지 못하는 도구는 `geometry`를 `point` 같은 타입으로 바꿔 import 한다. `CREATE EXTENSION` 줄과 부분 인덱스(`WHERE ...`)에서 막히면 그 줄을 지워도 그림에는 영향이 없다.
